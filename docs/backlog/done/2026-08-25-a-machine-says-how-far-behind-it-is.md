# Машина сама говорит, насколько она отстала от релиза

## Зачем

Панель, рисующая флот, хочет отвечать на вопрос «всё ли раскатано». Сегодня она может показать
только половину: `fleet --json` несёт версию, которая на машине **стоит**, и ничего о том, какая
**должна**. Вторую половину приходится добывать глазами из GitHub и сличать вручную — то есть
ровно та работа, ради устранения которой панель и существует.

Демон при этом уже знает ответ. `autoUpdateOnce` дёргает манифест релиза на каждом тике, сравнивает
и **выбрасывает результат**: ни одна поверхность его не видит, хотя это единственное место во всей
системе, которое смотрит на «последний релиз» с самой машины.

И у незнания здесь есть цена, которую легко проглядеть. Машина без сети до GitHub не отстала — про
неё просто ничего не известно. Нарисовать её актуальной значит соврать именно в том случае, когда
проверка нужнее всего.

## Результат

- У каждой машины в `list --json` и `fleet --json` есть блок про релиз: что стоит, что последнее,
  насколько отстали.
- «Актуальна» и «не знаем» различимы, а не свалены в одно.
- Свежесть ответа видна: сказано, когда проверяли в последний раз и удалась ли попытка.
- Отставание классифицировано владельцем схемы версий, чтобы каждый потребитель не переизобретал
  сравнение semver — и не расходился с соседом в том, что считать «сильно отстала».

## Форма

Машина сообщает факты **о себе**, и ничего о том, как её оценивать:

```jsonc
"release": {
  "current":   "0.35.0",                    // что стоит здесь
  "latest":    "0.35.0",                    // последний, который ЭТА машина сумела вычитать; null = не знаем
  "latestAt":  "2026-08-25T14:42:18Z",      // когда он опубликован; null на старом манифесте
  "checkedAt": "2026-08-25T14:46:00.000Z",  // когда пробовали в последний раз
  "ok":        true                         // удалась ли ПОСЛЕДНЯЯ попытка
}
```

Отставание считает **агрегат**, и эталон у него один на весь ответ:

```jsonc
{ "latest": "0.35.0", "latestAt": "…", "machines": [ { …, "release": {…}, "behind": "minor" } ] }
```

⚠️ **`behind` — не собственное утверждение машины, и это принципиально.** Машина, потерявшая
маршрут до фида релизов, помнит устаревший `latest`; если мерить её этой же памятью, она покажется
МЕНЬШЕ отставшей, чем есть, а иногда — актуальной. Ошибка направлена в успокаивающую сторону, ровно
там, где человек и полез проверять, потому что что-то не так. Поэтому эталон — лучший релиз,
известный ХОТЬ КОМУ-ТО в ответе, и меряются им все.

Три состояния остаются различимы, и третье как раз то, которое голый номер версии прячет:
**отстала**, **актуальна**, **никто не смог проверить** (`latest: null`, либо `ok: false` рядом с
запомненной версией). Последнее рисовать актуальным нельзя.

## Чего эта задача НЕ делает

Не превращает ccmux в инвентарь версий чужих проектов. Он умеет отвечать за свой бинарь на своей
машине — это честная граница. Версия библиотеки живёт не на машине, а в объявлении каждого
проекта, это другая ось, и сводить её в строку машины значит рисовать неправду.

## Что сделано

Форму согласовал с потребителем панели до реализации, и он нашёл в ней дефект, который я бы
выпустил: в первом варианте `latest` был свойством машины, и `behind` считался относительно её же
устаревшего представления. Правка принята целиком — эталон стал один на ответ.

### Механизм

- [x] `src/config/releaseCheck.ts` — запись о последней проверке (`release-check.json`):
      последний УСПЕШНО вычитанный релиз с датой публикации, когда пробовали, удалась ли попытка.
      Успешное значение сохраняется через последующие неудачи.
- [x] `autoUpdateOnce` записывает результат **до** того, как на него реагирует, и записывает
      неудачу тоже: машина, не дозвонившаяся до фида, не отстала — она перестала мочь сказать.
- [x] `behindBy` берёт эталон **аргументом**, а не из машины; `bestKnownRelease` выбирает лучший по
      флоту. Машина ВПЕРЕДИ релиза не отстала — это дев-чекаут, и красить его красным значит
      приучить не смотреть на цвет.
- [x] `fleetView` — единственное место, держащее эталон: `latest`/`latestAt` на уровне ответа,
      `behind` у каждой машины считается от него.
- [x] Манифест релиза несёт `releasedAt` (штампуется при публикации), поэтому отставание читается
      во времени, а не только в компонентах версии.
- [x] Человеческий вывод `ccmux fleet` называет последний релиз строкой сверху и помечает каждую
      машину: отставание, «release unknown here» или «cannot reach the release feed».

### Тесты

- [x] `test/release-standing.test.ts`, 9 проверок, включая именно тот случай, ради которого форма
      менялась: машина с устаревшей памятью показывает `minor`, а не `null`. 614 тестов зелёные.

Не превращает ccmux в инвентарь версий чужих проектов. Он отвечает за свой бинарь на своей машине —
это честная граница. Версия библиотеки живёт не на машине, а в объявлении каждого проекта: другая
