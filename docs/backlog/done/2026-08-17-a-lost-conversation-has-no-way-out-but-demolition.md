## Зачем

Уборка диска на сервере унесла транскрипты одной сессии. Защита сработала правильно: увидела,
что сессия уже запускалась, а её беседы нет, и **отказалась** молча начать новую под тем же
uuid — иначе владелец получил бы сессию с прежним именем и пустой памятью, не зная об этом.

Дальше защита замолкает. Она называет ровно один выход — «верни беседу на место и сделай
`start`» — и ничего не говорит про случай, когда беседа утрачена навсегда. А он и есть частый:
файл удалён, каталог проекта стёрт, процесса, державшего его открытым, нет.

Тогда единственный доступный путь — снести запись реестра и создать заново. Для этой сессии
обошлось: в ней не было ничего, кроме имени и папки. У сессии с настройками — режим прав,
оверрайд чата, промпт-модули, свой текст возобновления — тот же путь стирает всё это. Настройки
гибнут не потому, что они устарели, а потому что рядом пропал чужой файл.

Заодно вскрылось: `rm` снимает сессию с учёта, но её блок остаётся лежать на диске мёртвым
файлом с тем же именем. Сегодня он безвреден только по совпадению — не сойдётся ни поколение,
ни uuid.

## Результат

- У потерянной беседы есть штатный выход, который сохраняет саму сессию и её настройки.
- Сообщение блока называет оба случая: беседу можно вернуть — и беседы больше нет.
- Снятие сессии с учёта не оставляет за собой блок.

## План

- [x] `ccmux renew <name>` — сессии выдаётся свежая беседа; имя, папка, провайдер и все
      настройки остаются.
- [x] Живую беседу `renew` не выбрасывает без спроса: отказ с указанием файла, `--force` для
      осознанного случая.
- [x] `renew` снимает блок и запускает сессию.
- [x] Сообщение блока называет и `renew`, и возврат файла на место.
- [x] `rm` убирает блок вместе с записью реестра.
- [x] Тесты: сохранение настроек, отказ на живой беседе, снятие блока, чистота после `rm`.

## Acceptance
