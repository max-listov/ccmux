## Зачем

На сервере снесли `~/.cache/ccmux/` — законное действие: каталог называется кэшем и его
контракт прямо разрешает удаление. Данные пережили это ровно как задумано, реестр и конфиг
целы. Не пережил сам код.

В `paths.ts` про этот корень написано: «Deleting this costs exactly one `ccmux update`».
Утверждение неверно, и инцидент это доказал:

- `ccmux update` — **это и есть удалённый файл**. Инструмент не может починить сам себя.
- `ExecStart` boot-unit указывает туда же, поэтому демон не переживёт остановку.
- `ccmux.js.bak`, на который откатывается boot-guard при краш-лупе, лежал в том же
  каталоге — страховка исчезла вместе со страхуемым.
- Демон не заметил пропажи: решение об обновлении — чистое сравнение версий, вопроса
  «а файл на диске есть?» в нём нет.

Классификация верна по смыслу (бандл выводится из релиза заново) и неверна по последствиям:
путь восстановления проходит через то, что удалили. Живым остался только уже запущенный
процесс, который держит код в памяти — то есть система выглядела здоровой, будучи
невосстановимой.

## Результат

- Удаление кэша больше не выводит машину из строя: там остаётся только то, что
  действительно одноразово.
- Пропавший бандл восстанавливается сам, без рук.
- Расхождение «путь запуска указывает в пустоту» видно до того, как кто-то наберёт команду.
