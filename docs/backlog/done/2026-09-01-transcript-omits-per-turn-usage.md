# Транскрипт не несёт расход токенов по ходу

## Зачем

Строки журнала сессии несут `usage` на каждом ответе ассистента — это уже используется:

```ts
/** Context tokens used — the most recent assistant message's usage (input + cache). */
```

(`src/agent/claude/transcript.ts`, расчёт заполнения контекстного окна)

Но берётся из этого ровно одно число — общий размер контекста ПОСЛЕДНЕГО ответа. В записях
сообщений транскрипта расхода нет вовсе: ни входных токенов, ни выходных, ни кэша, ни разбивки
по ходам.

Из-за этого читатель транскрипта не может ответить на вопросы, которые задают о каждом ходе:
сколько он стоил, какой ход съел больше всего, растёт ли расход по ходу разговора. Данные для
ответа проходят через разбор и выбрасываются в тот же момент, когда из них берут одно число.

## Результат

- Запись ответа ассистента в транскрипте несёт usage этого ответа: входные, выходные и
  кэш-токены — теми же полями, что сообщает источник.
- Отсутствие usage у записи остаётся отличимым от нуля: старая строка без него даёт «неизвестно»,
  а не «ноль токенов».
- Существующий расчёт контекстного окна не меняет своего значения и продолжает опираться на тот
  же источник, а не на новую сумму.
