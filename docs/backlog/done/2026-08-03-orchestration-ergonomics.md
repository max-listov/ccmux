# Эргономика оркестрации

## Откуда задача
Агент на другом проекте разбирал ccmux ради координации «оркестратор → исполнитель» и наступил на
набор шероховатостей. Часть его выводов оказалась неверной (см. ниже), но три реальные дырки есть.

**Проверено по коду перед задачей:**
- ✅ `lastMessage` **уже есть** в `ccmux list --json` — парсить `transcript --tail 20` было не нужно.
  Но текст там клипнут до 280 символов (`LAST_MESSAGE_TEXT_LIMIT`), т.е. для «сними отчёт» нужен полный.
- ✅ `deferReady()` (`src/chat/deliver.ts:55`) — готовая логика «ход завершён добровольно»
  (спиннер погас + последнее сообщение assistant-текст + транскрипт стоит 6с). Её нужно просто
  переиспользовать, а не писать заново.
- 🔴 **Асимметрия в собственном UX:** `ccmux router on` честно печатает «applies on: ccmux restart …»,
  а `ccmux chat on` — нет. Человек включает чат, шлёт `--defer`, ничего не работает, причина неочевидна.

## Скоуп (осознанно узкий)
Делаем три маленькие автономные вещи + документацию. **НЕ делаем:** смену дефолта доставки
(`--defer` дефолтом — решение Max: не трогаем) и кросс-машинный чат / Фазу 4 (не усложняем;
следствие: оркестратор и исполнители должны жить на одной машине).

1. **`ccmux wait <name> [--timeout N]`** — блокирующее «дождись, пока сессия договорит»; exit 0 когда
   ход стабильно завершён, exit 1 по таймауту/неизвестной сессии. Переиспользует `deferReady`.
   Ценность: убирает поллинг `ccmux list` в цикле, работает **без чата** и без всякой оркестрации.
2. **`ccmux transcript <name> --last-message`** — полный текст последнего ответа агента (plain text,
   без JSON-обвязки), для «сними отчёт» одной командой.
3. **`ccmux chat on/off` подсказывает следующий шаг** — что применится на рестарте (как `router on`)
   и как слать. Плюс: применить массово теперь можно `ccmux restart --all`.

## «Чтобы не тупили» — discoverability
- README: короткий раздел-рецепт **Coordinating agents** (включить чат → рестарт → `msg --task`
  → `wait` → `transcript --last-message`), с явной оговоркой «одна машина».
- Примеры (`example`) в `COMMANDS` для новых/затронутых команд — они видны в `ccmux help <cmd>`.
- Сообщения самих команд подсказывают следующий шаг, а не только факт («chat enabled» → что дальше).
