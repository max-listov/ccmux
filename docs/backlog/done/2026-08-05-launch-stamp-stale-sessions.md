# Видеть, каким сессиям рестарт реально нужен

## Проблема

Всё, что влияет на поведение агента, вставляется **в момент запуска**: системный промпт (включая
chat-блок и prompt-модули), `--settings` (Stop-хук чата, statusline, RC), permission mode, код
самого супервизора. Значит любое изменение этих вещей действует только после рестарта сессии.

Система это **знает** и даже говорит: `ccmux update` пишет «sessions pick up new code on next
restart», `chat on` / `router on` / `mode` — «applies on: ccmux restart `<name>`». Но говорит
**один раз, в момент действия**, и через минуту это ушло со скролла.

Никакой пометки на сессии нет. Проверено по коду: `VERSION` фигурирует только как версия БИНАРЯ
(шапка `list`, `doctor`, `fleet`, `help`, TUI, `update`), в статус-файлах сессии лежат лишь
`lifecycle`, `chathold`, `metrics`. Слов «stale / outdated / needs restart» в коде нет вовсе.

Следствие ровно то, во что мы упёрлись: флот обновлён, а какие сессии реально несут новый
промпт — держится у человека в голове. И на вопрос «я включил чат, применилось?» сегодня можно
ответить только вручную.

## Почему НЕ «сравнивать версию»

Версия — грубая мерка, и врёт в обе стороны:
- релиз без изменений промпта пометил бы **все** сессии, хотя рестарт ничего бы не дал;
- `ccmux chat on` версию не двигает вообще, а рестарт после него **обязателен**.

Правильная формулировка не «сессия старая», а **«если перезапустить сейчас — она получит другое»**.
Это проверяемо напрямую, без эвристик.

## Дизайн

**Штамп при запуске.** `_run` перед спавном кладёт рядом с существующими статус-файлами
`<name>.launch.json`: версия бандла, хэш нормализованного argv запуска и несколько простых полей
(permission mode, chatEnabled, prompt-модули).

**Нормализация — важная деталь.** В argv есть ровно одна волатильная часть: uuid беседы
(`--resume <uuid>` / `--session-id <uuid>`), который меняется при форке беседы. Он заменяется
плейсхолдером, а `historyPresent` при вычислении фиксируется — иначе первый же форк пометил бы
сессию «устаревшей» без причины. Всё остальное в argv (бинарь, промпт, settings, режим, флаги)
как раз и есть политика, которую мы хотим сравнивать.

**Сравнение.** `list` пересчитывает штамп из текущего конфига и сравнивает с записанным. Не
совпало — сессия помечена, и **названо, что именно** разошлось: `code` (версия), `chat`, `mode`,
`modules`, либо `config` (прочее — правка промпта, ownerLang, extraFlags).

**Отсутствие штампа = «не знаю», а не «устарела».** Иначе первый же апгрейд самого ccmux покрасил
бы весь флот без причины.

Провайдер-агностично: хэш берётся с того же `buildArgv`, которым сессия и запускается, поэтому
новый агент не требует отдельной поддержки.

## Что НЕ делаем
Не перезапускаем ничего автоматически — пометка информирует, решает человек. Не вводим «возраст»
и эвристики по аптайму. Не сравниваем коммиты: коммит и поведение сессии связаны слабо.

### Проверено вживую, а не только тестами
Одноразовая сессия: сразу после запуска — `-`; `ccmux chat on` (версия НЕ меняется) → `chat`;
поверх `ccmux mode plan` → `chat,mode`; в JSON `['chat','mode']`. Это ровно тот случай, который
сравнение версий не поймало бы вовсе.

### Побочное наблюдение
На момент внедрения весь флот показывает `-`, потому что штампов ещё нет ни у кого: колонка
начинает работать с первого рестарта каждой сессии. Это осознанно — «не знаю» не красим.
