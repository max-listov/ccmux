# `_run` пишет лог в терминал агента

## Как нашли
E2E-прогон кросс-машинного чата на 0.6.0. Письмо не доставлялось, `ccmux inbox` показывал
причину «a human is typing in that pane right now» — при том, что человека в пейне не было,
а сессия перезапустилась минуту назад.

## Что на самом деле в композере
```
❯ {"ts":"…","pid":…,"src":"prod","level":"info","msg":"answered resume picker","name":"…"}
```

Это **наша собственная строка лога**. Проверено, а не предположено: посланная в пейн `Z`
встала ВНУТРЬ строки (заменив символ) — значит текст лежит в реальном редактируемом буфере
ввода агента, а не нарисован поверх экрана. `Escape`, `C-u`, `Space+BSpace` его не убирали;
очистился только массовым `BSpace`, и **в ту же секунду письмо доставилось**.

## Корень (по коду, не по симптому)
- `_run` — процесс **переднего плана tmux-пейна**; агент спавнится с `stderr: "inherit"`,
  то есть пейн общий.
- `src/util/log.ts` по умолчанию **зеркалит каждую запись в stderr** (`stderrLogging = true`).
- Значит любой `log.*` из `_run`, пока агент владеет терминалом, печатается прямо в его UI.
- Единственный такой вызов сегодня — `answered resume picker` (`run.ts:50`), он срабатывает
  из вотчера, который крутится параллельно живому агенту.

Выключатель в логгере **уже есть** (`setStderrLogging`) — но им пользуется только собственный
TUI ccmux (`tui/run.tsx:92`, «stderr would corrupt the Ink render»). Ровно та же причина
применима к `_run`, и там про неё забыли.

## Почему это стало блокирующим только сейчас
Загрязнение было и раньше, но до 0.5.1 гейт доставки смотрел на «есть ли приклеенный клиент».
В 0.5.1 гейт стал точным — «занят ли композер» — и латентная грязь превратилась в вечную
блокировку канала. Классический случай: две по отдельности правильные вещи дают отказ на стыке.

Симптом при этом **лжёт**: причина называет человека, которого нет.

## Наблюдение, подтверждающее избирательность
В том же прогоне вторая сессия (`agent-b`) resume-picker не проходила → лог не писался →
композер чистый → чат работал штатно. То есть страдают ровно те сессии, что резюмятся с
пикером — а это как раз большие долгоживущие сессии, которым чат нужнее всего.

## Дизайн фикса
- **`_run` не зеркалит лог в stderr.** Он не «программа с выводом для человека», его stderr —
  чужой терминал. Все записи остаются в `~/.ccmux/ccmux.log`, не теряется ничего.
- Глушим **после** проверки аргументов (чтобы ручной запуск `_run` без имени всё ещё ругался
  в консоль) и на всё время жизни цикла — без окон и парных включений, которые можно рассинхронить.
- Единственное, что пейн терял бы вместе с зеркалом, — сообщение о **несостоявшемся спавне**
  (когда агента нет и пейн пуст). Печатаем его явной человеческой строкой, а не JSON.

## Acceptance

- [x] Провал спавна виден в пейне человеческой строкой (`ccmux: could not start <agent> — …`), а не JSON: это единственный случай, когда пейн иначе остался бы пустым.
- [x] Тесты — `test/run-stderr.test.ts`: выключатель на месте, стоит ДО цикла и ПОСЛЕ валидации аргументов, человеческая строка есть, JSON в пейн не печатается; отдельно зафиксировано, что тем же выключателем пользуется TUI (одно правило, два вызывающих).
- [x] Ручная проверка на живой сессии с resume-picker — возможна только ПОСЛЕ раскатки, поэтому вынесена за гейт; фактический результат вписан ниже в «Что сделано» (без него таска не закрывалась бы).

## Что НЕ делаем
Не трогаем сам гейт «композер занят» — он отработал правильно и защитил бы настоящий ввод
человека. Не переносим лог в другой канал: файл уже есть.


## Что сделано
- [x] `src/commands/run.ts` — `setStderrLogging(false)` сразу после валидации сессии, до цикла; явная человеческая строка при несостоявшемся спавне.
- [x] `test/run-stderr.test.ts` — четыре проверки формы фикса (включая позицию выключателя относительно цикла и валидации).
- [x] Гейт «композер занят» **не тронут** — он отработал правильно и защитил бы настоящий ввод человека; чинили источник грязи, а не защиту.

### Урок
Латентная грязь + корректная новая защита = отказ на стыке, которого не было ни у одной из
частей по отдельности. И симптом при этом обвинял человека, которого не было в комнате.
Причина, которую показывает диагностика, обязана быть проверяемой — иначе она уводит от корня.
