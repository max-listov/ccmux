# Доставка при приаттаченном клиенте

## Проблема (поймана на живом инциденте)
На host-b письмо `agent-a → agent-b` (`--defer`, 1634 симв.) висело недоставленным, хотя чат
включён у обоих, сессия idle, меню нет. Диагностический лог демона показал причину:

```
"chat delivery held — human attached to pane", to:"agent-b", from:"agent-a"   ← каждые 3с
```

Max смотрел эту сессию через `tmux a`. Гейт `hasAttachedClient` холдит доставку **на всё время
подключения** — то есть «я смотрю» = «канал молча мёртв», причём бессрочно.

**Настоящая опасность, от которой защищались, ýже:** доставка = `send-keys` литерала **+ Enter**.
Если человек НАБРАЛ строку и не отправил — наш текст допишется к его строке, а наш Enter отправит
эту кашу. Просто СМОТРЕТЬ при этом абсолютно безопасно.

## Решение
Гейт «приаттачен» → гейт «человек сейчас печатает», по двум реальным сигналам:

1. **Поле ввода непустое** — строка `❯ …` в нижней рамке пейна содержит текст (главный сигнал:
   если пусто, наша вставка ничего не портит). Claude-специфично → живёт в провайдере.
2. **Клиент трогал клавиши только что** (`client_activity` из tmux, окно ~3с) — страховка от
   попадания ровно между нажатиями.

Ни одного → **доставляем, даже если человек приаттачен**.

Без изменений: холд на интерактивном меню (`atInteractiveMenu`) — там инжект выбрал бы пункт,
который агент не выбирал. Это настоящая опасность, она остаётся.

### Проверено на живых пейнах (детект работает)
| сессия | строка ввода | вердикт |
|---|---|---|
| `agent-b`, `agent-c`, `agent-d` | `❯ ` (пусто) | доставлять |
| `agent-e` | `❯ <текст, набранный человеком>` | человек набрал → холд |
| `agent-f` | `❯ {"ts":"…"` (в поле мусор из лога) | занято → холд |

Структура низа пейна стабильна: `──── <rc> ──` / `❯ <ввод>` / `────` / статуслайн. ⚠️ Нельзя
грепать `^❯` по всему пейну — Claude рисует `❯` и для прошлых сообщений в истории; смотреть только
нижние строки.
