# Запись «не ушло» должна досылаться, а не лежать

## Что показал живой прогон

Агент на машине B ответил на вопрос агента с машины A — содержательно и правильно. Отправка
не прошла: в тот момент у машины B не было маршрута до A. Мы это **честно записали**:

```
[04:39:43] agent-b ⇢ host-a:agent-a: Привет! (1) … (2) …   [NOT SENT — transport failed]
```

И на этом всё. Никто запись больше не читает. Агент отчитался и пошёл дальше — **отчёт
потерян**, хотя он существует и лежит на диске. Второй агент ждал ответа, которого не будет.

Честная запись вместо тишины — это уже прогресс (раньше не было и её). Но журнал сам по себе
работу не доделывает.

## Почему маршрут вообще пропадает — и почему это НЕ чиним

Проверено на живых машинах, а не по документации:

```
машина A пускает:  <mac-key-1> · <mac-key-2>
машина B пускает:  <mac-key-1> · <mac-key-2> · <deploy-key>
```

Ключа B на A нет, ключа A на B нет. Единственный ключ, открывающий обе, — на ноутбуке
владельца. Межсерверный проход существует только пока живо его подключение (ssh
agent-forwarding), и это **осознанная модель**: взломали одну машину — соседняя не досталась,
потому что красть нечего.

Раздать серверам ключи друг другу = сломать ровно ту защиту, ради которой всё так устроено.
**Не делаем.** Значит транзит по своей природе прерывистый, и правильный ответ — не «держать
канал всегда», а «пережить отсутствие канала».

## Дизайн

### 1. Идемпотентность отправки (обязательное условие любого ретрая)
Сейчас каждая попытка порождает на приёмной стороне сообщение со **свежим** uuid. Значит
повтор рискует продублировать письмо, если первая попытка на самом деле доехала, а мы неверно
прочли отказ (например, ssh убили по таймауту уже после того, как удалённая сторона записала
сообщение — реальный сценарий, отмеченный ещё при ревью fleet-адресации).

Лечится тем же приёмом, что и origin: **id едет переменной окружения**, приёмник берёт его
вместо собственного uuid и **молча игнорирует id, который уже есть в его ledger**. После этого
повтор безопасен по построению, а не «скорее всего обойдётся». Старый ccmux переменную не знает
→ ведёт себя как сегодня (новый id каждый раз), то есть деградация тихая и без порчи.

### 2. Досыл
Демон тем же тиком, что доставляет чат, берёт из outbox неудачные отправки и пробует снова.
Границы, чтобы это не превратилось в вечный шторм:
- только `kind: "msg"` (у `restart --then` повтор небезопасен: это не сообщение, а действие);
- только свежие (окно по времени) — недельной давности письмо досылать бессмысленно и вредно;
- ограниченное число попыток за тик, чтобы залипший хост не съедал весь цикл;
- успех фиксируется в **отдельном ack-файле**, как это уже сделано для чата, а не переписыванием
  журнала: outbox остаётся append-only историей попыток.

### 3. Необязательный preflight
Прерывистость маршрута часто лечится одной локальной командой (у владельца это перепривязка
ssh-сокета). Даём **обобщённый** необязательный хук `transitPreflight` в machine.json: если задан
— выполняется перед пачкой ретраев, не чаще. Никаких имён чужих скриптов в коде: ccmux —
публичный инструмент и не должен знать про личную обвязку конкретного человека.

## Acceptance
- [x] id сообщения едет на приёмную сторону (`CCMUX_MSG_ID`, той же переменной-дорогой, что и origin); приёмник использует его как id записи.
- [x] Повторная доставка того же id — no-op. **Проверено вживую**: вторая отправка ответила `already delivered (…) — retry ignored`, exit 0, в ledger осталась ОДНА запись.
- [x] Старый ccmux не ломается — неизвестную переменную игнорирует, ведёт себя как сегодня (свой id каждый раз).
- [x] Демон досылает неудачные `msg` из outbox тем же тиком, что доставляет чат; успех — в отдельный ack-файл, журнал попыток не переписывается.
- [x] Ретраи ограничены: окно 1 час, `MAX_PER_TICK`, дедуп по id, `restart-then` исключён явно.
- [x] `chat log` показывает «sent later, on retry» вместо `NOT SENT` для того, что доехало.
- [x] `transitPreflight` — необязательный argv-МАССИВ (шелл его не видит), по умолчанию отсутствует; никаких имён чужих скриптов в коде.
- [x] Тесты — `test/fleet-flush.test.ts`: кандидаты, окно, дедуп, исключение `restart-then`, битая дата, round-trip ack, смена формулировки в логе.
- [x] `bun run check` зелёный — 294 pass.

## Что НЕ делаем
Не раздаём серверам ключи. Не поднимаем постоянный туннель. Не делаем ретраи для `restart --then`.
Не вводим экспоненциальные бэкоффы и приоритеты — очередь маленькая, тик и так редкий.

ключ — на ноутбуке владельца. Чинили не «держать канал всегда», а «пережить его отсутствие».
