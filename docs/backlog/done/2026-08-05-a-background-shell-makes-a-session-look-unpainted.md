# Фоновый шелл делает сессию «неотрисованной»

## Что видно снаружи

На простаивающем флоте две сессии из двенадцати вели себя не как остальные:

```
host-a:agent-a               working   Opus 5      2d4h
host-a:agent-b               working   Opus 5      2d4h
```

Обе на самом деле **простаивают**: ход закончен, отчёт написан, композер пуст. Но:

```
$ ccmux wait agent-a --timeout 12
agent-a: timed out after 12s — the recipient's UI has not painted yet (starting or resuming)
```

Сессия работает двое суток. «UI ещё не нарисован» — заведомая ложь.

## Корень

`READY_RE` опознавал отрисованный интерфейс по строке `shift+tab to cycle`. Это
**подсказка**, а не элемент интерфейса. Claude рисует футер одной строкой и, когда
у агента есть фоновые шеллы, ставит их счётчик **вместо** подсказки:

```
⏵⏵ bypass permissions on (shift+tab to cycle) · ← for agents     ← подсказка есть
⏵⏵ bypass permissions on · 3 shells · ← for agents               ← её вытеснил счётчик
```

Замер по всем 12 локальным сессиям: подсказки нет ровно у тех двух, у которых есть
фоновые шеллы. Ширина пейна ни при чём — две другие широкие сессии тоже 180 колонок и подсказку
показывают.

Итог: **любой агент, оставивший фоновую команду, для ccmux навсегда «ещё не
нарисовался»** — а `run_in_background` эти агенты используют постоянно.

## Почему это дорого

Один признак кормит три разных решения, и все три ломаются одинаково молча:

1. **Вся отложенная почта встаёт навсегда.** `not-drawn` — жёсткий гейт в `turnState`
   (введён в 0.10.0 осознанно: клавиша, проглоченная недорисованным интерфейсом,
   помечается доставленной и теряется). Сессия с фоновым шеллом не получит ни одного
   письма — и в `inbox` будет написано «интерфейс ещё не нарисован».
2. **`wait` не отвечает никогда** — таймаут с ложной причиной. Это ровно тот сценарий,
   ради которого `wait` и писался: агент ждёт коллегу, который свободен.
3. **`list`/`fleet` показывают «working» вместо «idle».** `resolveLiveState` при
   ненарисованном пейне не доверяет ему и падает обратно на `lifecycle`, а там
   застрявший `working` — Stop-хук по прерванному ходу не срабатывал.

То есть один неверный признак дал три симптома в трёх подсистемах, и ни один из них
не выглядел как «у нас плохой признак».

## Что делаем

Признак опознаёт **структуру** интерфейса, а не текст подсказки:

- футер режима (`⏵⏵ … on`) — инвариант, он есть в любом режиме и не вытесняется;
- `? for shortcuts` — футер дефолтного режима (проверено в бандле claude 2.1.222);
- `esc to interrupt` — интерфейс во время хода;
- `shift+tab to cycle` — оставляем, но уже как один из нескольких, а не единственный.

Пока хоть один маркер на месте — интерфейс нарисован. Косметическая правка футера
больше не способна обнулить признак.
