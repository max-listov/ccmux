# Ответ провода читается целиком

## Откуда

Транспорт выпустил версию, где локальная дверь версионирует свой контракт и различает **вид**
отказа. Проверено на живой машине: ответ вызова несёт `v: 2`, `refusal`, `retryAfterMs`, а поле
`protocol` из статуса исчезло. ccmux парсил только `code/stdout/stderr/failure/detail/truncated` —
то есть работал (лишние ключи отбрасывались молча), но не пользовался ничем новым.

## Что было не так

**1. Вид отказа схлопывался в строку.** Дверь различает `capacity` (временный — ретрай правильный),
`policy` и `request` (постоянные — ретрай ничего не изменит). ccmux считал любой отказ одинаковым, и
делал обе ошибки сразу: час ретраев против отказа, который никогда не поменяется, и «занят» в
отчёте, выглядящий как поломка.

**2. Версия контракта игнорировалась.** Контракт двери прямо просит читателя **сравнивать** `v`, а
не матчить литералом: без сравнения дверь с незнакомым контрактом неотличима от испорченного ответа,
и читатель идёт искать сломанный агент вместо расхождения версий.

**3. Найдено по ходу — молчаливая потеря почты.** Проход дренажа outbox читал ssh-карту напрямую:

```ts
const alias = fleet[target.machine];
if (alias === undefined) { appendOutboxAck(...); continue; }  // «машина ушла из карты»
```

Машина не уходила из карты — она в **другой** карте. Замерено на живом флоте: обе серверные ноды
достают ноутбук **только по проводу** и не имеют для него ssh-алиаса вовсе. То есть каждый ретрай в
том единственном направлении, ради которого провод и появился, помечал письмо доставленным и
выбрасывал его. Без ошибки, без строки в логе, с exit 0.

Тот же класс дефекта, что чинили накануне в reply-подсказке: код консультируется с одной картой
транспорта там, где решение принимает резолвер, знающий обе.

## Что сделано

- `src/fleet/wire.ts` — `v` сравнивается (`DOOR_API_VERSION`), несовпадение называется словами;
  читаются `refusal` и `retryAfterMs`; `refusalIsPermanent` даёт `undefined` для старой двери —
  «неизвестно», а не догадка в любую сторону.
- `src/fleet/transport.ts` — `RemoteResult` получил `permanent` и `retryAfterMs`;
  `queuedForRetryNotice` при постоянном отказе больше не обещает автоматическое восстановление.
- `src/fleet/flush.ts` — ретрай идёт через `routeFor` + `runPeer`, то есть тем же резолвером, что и
  отправка; постоянный отказ оседает с записью в лог вместо часа ретраев; единственный законный
  случай «осадить» — цель, которой нет ни в одной карте.
- `test/wire-door-v2.test.ts` — 6 тестов, включая регрессию на потерю почты.
- `docs/architecture/peer-routing.md`, CHANGELOG.

Живые пробники: вызов до обеих серверных нод через дверь v2 отвечает `ccmux 0.29.0`; вызов команды
не из allowlist даёт `denied/policy` → `permanent = true` → честный текст «refused identically on
every retry… waiting will not deliver it».

## Acceptance

- [x] Вид отказа различается; постоянный не ретраится и не описывается как «доставится само».
- [x] Версия контракта двери сравнивается; несовпадение называется, а не выглядит как испорченный ответ.
- [x] Лишние ключи в ответе двери по-прежнему проходят — апгрейд транспорта не ломает ccmux.
- [x] Ретрай использует тот же резолвер, что и отправка; пир, доступный только по проводу, больше не
      считается недоступным.
- [x] Единственный случай «осадить письмо» — цель вне обеих карт, и он логируется.
