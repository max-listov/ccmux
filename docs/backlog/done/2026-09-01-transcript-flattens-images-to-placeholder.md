# Транскрипт схлопывает изображение в «[image]»

## Зачем

Разбор содержимого переписки превращает блок изображения в literal-строку:

```ts
case 'image':
  return '[image]';
```

(`src/agent/claude/transcript.ts`, ветка разбора блоков контента)

Читатель транскрипта получает сообщение, где вместо картинки стоит текст `[image]`. Показать
изображение он не может ничем: в записи нет ни ссылки, ни идентификатора вложения, ни типа —
только слово. При этом:

- байты картинки присутствуют в исходной строке журнала сессии;
- у ccmux уже есть подсистема вложений (`src/attachments/`) со своим хранилищем, валидацией
  и лимитами, то есть адресовать изображение есть чем.

Скриншот — обычная часть разговора с агентом: им показывают экран, ошибку, макет. Переписка,
в которой на месте каждого такого сообщения стоит `[image]`, теряет ровно то, ради чего его
отправляли, и восстановить это из транскрипта невозможно.

## Результат

- Блок изображения в транскрипте несёт ССЫЛКУ на содержимое (идентификатор вложения или иной
  адрес, по которому байты можно получить), а не заглушку-строку.
- Известен тип содержимого (media type) и, если есть, размеры — читателю хватает, чтобы решить,
  как показать, не скачивая всё подряд.
- Байты изображения НЕ едут внутри записи транскрипта: список сообщений остаётся дешёвым,
  содержимое запрашивается отдельно и по требованию.
- Изображение, которое не удалось разобрать или которое превысило лимит, остаётся отличимым от
  «изображения не было»: причина названа, а не подменена заглушкой.

## Что сделано

- [x] Блок изображения стал своим видом сообщения (`image`) вместо текста `[image]`:
      `TranscriptKindSchema` в `src/config/schema.ts`, разбор в `src/agent/claude/transcript.ts`.
      Слова на месте картинки больше нет — оно было строкой, которую ничем нельзя было превратить
      обратно в изображение.
- [x] `TranscriptImageSchema`: адрес `<uuid записи>#<номер блока>`, media type, размер и дайджест
      содержимого. Адрес стабилен ровно столько, сколько живёт строка: журнал только дописывается,
      строка не переезжает.
- [x] Байты в записи НЕ едут: список сообщений читается постоянно (он же `lastMessage` в
      `list --json`), и таскать через него картинки значит заставить каждый листинг платить за
      содержимое, которого почти никто не просил. Тест это и проверяет — base64 в записи нет.
- [x] Недоступное изображение называет причину: `unsupported-source` (источник — чужой URL, и
      выдать адрес, на который мы не ответим, хуже отказа), `malformed`, `too-large`. «Не читается»
      и «картинки не было» требуют от читателя разных действий.
- [x] Чтение по адресу: `readImage` и `ccmux transcript <name> --image <address>` отдаёт data URL.
      Читателю не нужно самому разбирать журнал сессии.
