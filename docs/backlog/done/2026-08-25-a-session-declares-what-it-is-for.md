# Сессия объявляет, за что отвечает, и адрес выбирается по этому

## Зачем

Сессия объявляет о себе имя, каталог, провайдера, режим и набор модулей промпта. Чего она не
объявляет — **за что отвечает**. Поэтому адресат выбирается по имени, а имя выбирают по названию
проекта; у проекта же бывает несколько сессий, и решения по конкретному контракту принимает одна
из них.

Замеренный случай: отправитель написал «по имени проекта», письмо ушло успешно и попало в сессию,
которая ведёт другую часть работы и по этому вопросу ничего не решает. Ошибка не проявилась ничем:
адрес разрешился, доставка прошла, экзит-код нулевой.

Это тот же класс, ради которого в адресе появилась машина — только на уровень ниже. `fleet`
показывает, что `api` на одной машине и `api` на другой это разные сессии; он не показывает, что
две сессии на ОДНОЙ машине занимаются разным.

## Чего делать не надо

**Поля, которое только показывается, недостаточно.** Ошибка совершается в момент выбора адреса, и
украшение в выводе `list` в этот момент никто не читает. Признак обязан стоять там, откуда адрес
копируют, и обязан участвовать в разрешении адреса — иначе это документация, а не механизм.

**И роль не должна стать вторым именем, которое разъезжается с первым.** Если её задают один раз
при создании и она дорога в изменении, через неделю она врёт — и врёт хуже, чем её отсутствие,
потому что ей уже верят. Пример того, как это делается правильно, в системе есть: `promptModules`
хранит только ИМЯ модуля, а текст — версионируемый код, поэтому модуль не может протухнуть.

## Результат

- У сессии есть объявленная роль, меняемая отдельным глаголом так же дёшево, как `mode` и `chat`.
- `ccmux fleet` показывает её в той же строке, из которой копируют адрес.
- Адресовать можно по роли, и **неоднозначность отказывает, называя кандидатов**: адрес, который
  подходит двум сессиям, не выбирает одну из них молча.
- Отсутствие роли — обычное состояние, а не ошибка: сессия без неё адресуется по имени, как
  сегодня.

## Что доступно потребителю до этого

`ccmux list --json` на нужной машине отдаёт по каждой сессии `dir` и `lastMessage`. Рабочий
каталог — ближайшее к роли, что уже объявлено, а последнее сообщение говорит, чем эта сессия
занята на самом деле. Это не замена, но это способ выбрать правильный адрес сегодня, не угадывая
по имени.

## Что сделано

Приоритет и форму согласовал с потребителем, который принёс случай. Он же назвал причину сделать
роль первой, и она лучше моей: **промах по роли ТИХИЙ** — имя разрешилось, доставка прошла, код
ноль, и час прошёл в уверенности, что владелец получил отчёт. Ложная уверенность дороже отказа.
Отсутствие внешнего адреса ломается громко и человеком уже закрыто вручную.

### Механизм

- [x] `role` в `SessionSchema` (`src/config/schema.ts`) — свободный текст под правилами
      address-токена, не enum: полезные роли это словарь проекта.
- [x] `setSessionRole` в `src/config/sessions.ts` — применяется сразу, не launch-time, и намеренно
      не входит в `computeStamp`: объявление роли никогда не красит сессию как требующую рестарта.
- [x] `src/chat/roleAddress.ts` — резолвер: сигил `@` как отдельное пространство имён, отказ при
      неоднозначности, отказ с кандидатами.
- [x] `src/commands/role.ts` — `ccmux role <имя> <роль|--none>` и без аргументов список того, что
      кому отвечает, с пометкой на общих ролях.
- [x] `src/commands/msg.ts` — `@роль` разрешается локально и на удалённой машине; удалённая роль
      считается по ТОМУ ЖЕ ответу `list --json`, из которого берётся личность пира.
- [x] `ccmux fleet` показывает роль в строке адреса — там, откуда адрес копируют.

### Отказ — это и есть механизм

- [x] Роли нет ни у кого — отказ говорит, как её объявить, с адресом нужной машины.
- [x] Роль есть у других — отказ перечисляет объявленные.
