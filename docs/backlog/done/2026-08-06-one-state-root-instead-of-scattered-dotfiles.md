# Один корень состояния вместо россыпи дотфайлов

## Что не так

ccmux держит своё состояние в **двух местах сразу**, и половина его лежит россыпью
дотфайлов прямо в домашней папке:

```
~/.ccmux/          app/  releases/  staged/  status/  ccmux.log  boot-attempts
~/.config/ccmux/   machine.json
~/.ccmux-sessions          ← реестр
~/.ccmux-chat.jsonl        ← леджер переписки
~/.ccmux-chat-cursors.json
~/.ccmux-chat-ack.jsonl
~/.ccmux-outbox.jsonl
~/.ccmux-outbox-ack.jsonl
```

Отсюда три следствия, и все три встретились вживую.

**1. Раскладка расходится между машинами — и это заложено в конструкцию.**
`sessionsFile` — **обязательное** поле конфига. Значит на каждой машине человек
вписывает путь руками, в свой день. Четыре машины — четыре независимых решения.
На одной из них путь указал в чужую домашнюю папку, и туда же уехали остальные пять
файлов: их расположение выводится из `dirname(sessionsFile)`.

**Путь к файлу диктует раскладку каталога** — вот корень. Один невнимательный
параметр утаскивает за собой пять чужих файлов.

**2. На вопрос «это можно удалить?» нельзя ответить.** Дотфайлы без расширений
рядом с рабочими папками выглядят мусором. Реестр — единственный файл, чья потеря
делает все сессии бесхозными, — выглядит ровно так же, как всё остальное.

**3. Сроки жизни перемешаны.** `app/`, `releases/`, `staged/` восстанавливаются
одной командой обновления. `status/` и реестр — нет. Лежат вперемешку.

## Что делаем

Раскладку задаёт **каталог**, а не файл; каталоги разделены **по сроку жизни** и
выводятся автоматически, так что новая машина ложится правильно, никого не спрашивая.

```
<config>/ccmux/    machine.json                     правит человек
<state>/ccmux/     sessions.jsonl                   переживает всё
                   chat.jsonl  chat-cursors.json  chat-ack.jsonl
                   outbox.jsonl  outbox-ack.jsonl
                   status/  ccmux.log[.1|.2]  boot-attempts
<cache>/ccmux/     app/  staged/  releases/         восстановимо
```

Корни берутся из стандартных переменных окружения для конфигурации, состояния и кэша,
с обычными для платформы дефолтами. Ничего не нужно вписывать руками.

### Ключевые решения

- **`sessionsFile` исчезает.** Вместо него `stateDir` — **каталог**, необязательный,
  с выводимым дефолтом. Обязательное поле порождало разъезд; необязательное с
  дефолтом — нет. Тесты и изолированный dev-инстанс продолжают им пользоваться как
  штатной точкой подмены, и это его единственное назначение.
- **Имена внутри каталога — нормальные.** Без префикса `.ccmux-`, с расширениями.
  Реестр наконец становится `sessions.jsonl` — сегодня он единственный файл без
  расширения, хотя это построчный JSON.
- **Никакого легаси.** Ни двойного чтения, ни подхвата старых путей, ни команды
  миграции в коде. Перенос выполняется **один раз, операцией**, и старые файлы
  удаляются рукой человека после проверки.
- **`doctor` печатает раскладку.** Расхождение должно быть видно командой, а не
  случайной уборкой.

## Почему без легаси-подхвата

Двойное чтение («нет нового — возьми старое») выглядит безопаснее, но именно оно
консервирует проблему: обе раскладки остаются валидными, и через полгода никто не
помнит, какая настоящая. Правило проекта на этот счёт однозначно — меняем API,
переписываем все точки вызова в одном заходе.

Цена — узкое окно между выкаткой и переносом, когда новый код смотрит в пустой
каталог. Оно **безопасно по построению**: пустой реестр означает «нечего
супервайзить», демон никого не трогает, работающие сессии продолжают жить. Порядок
операций (ниже) закрывает и его.

**Перенос (по одной машине, порядок обязателен)**

1. остановить демон;
2. создать каталог состояния;
3. **скопировать** шесть файлов под новыми именами (копия, не перемещение);
4. убрать `sessionsFile` из конфига машины;
5. обновить бинарь до новой версии;
6. поднять демон, проверить, что все сессии на месте;
7. только теперь удалить старые файлы — руками.

Копия вместо перемещения делает шаг обратимым: реестр — единственный файл, чья
потеря стоит дорого, а путь отхода (`adopt` по uuid) хоть и существует, но
пользоваться им не хочется.
